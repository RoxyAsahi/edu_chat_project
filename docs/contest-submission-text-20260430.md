# UniStudy 参赛报名文字材料

适用项目：第五届上海市青少年人工智能与编程实践活动 / 人工智能系列 / 创新实践项目  
作品名称：UniStudy

## 作品介绍

UniStudy 是一款面向多学科复习场景的桌面端个人 AI 学习终端。作品针对学生在复习过程中常见的资料分散、问答零散、笔记难沉淀、复习训练不连续等问题，将 Source 资料管理、AI 对话学习、Notes 笔记沉淀、学习分析、选择题和闪卡生成整合到同一个学习流程中，帮助学习者围绕一个学科或专题持续完成“导入资料、提出问题、理解知识、整理重点、生成练习、回顾复习”的闭环。

作品采用 Electron 桌面端形态开发，支持多学科入口、多话题历史、文件附件管理、PDF/DOCX/文本等资料导入、话题级资料绑定与检索、流式 AI 对话、高表现力消息气泡渲染、聊天内容收藏转笔记、Markdown 导出等功能。与普通聊天工具相比，UniStudy 更强调学习过程的连续性：每个话题都可以绑定自己的资料、保留对话历史和笔记，AI 的回答不只是一次性结果，还可以继续沉淀为复习资料，并进一步转化为练习题和闪卡。

本作品的创新点主要体现在学习流程设计上。第一，作品通过话题级 Source 绑定，让不同复习专题使用不同资料集合，减少资料混杂造成的干扰。第二，作品把 AI 对话结果与 Notes 笔记系统连接起来，使有价值的解释、总结和例题分析能够长期保存。第三，作品支持基于笔记继续生成深度分析、选择题和闪卡，让资料和笔记能够继续服务复习训练。第四，作品强化了 AI 消息气泡的渲染能力，使 Markdown、代码、图片、KaTeX、Mermaid、HTML/SVG 片段以及部分 3D 学习内容能够在聊天区中更清晰地呈现，提升学习阅读和演示效果。

## 创作说明

本项目的创作起点来自我们在真实学习中的观察：复习时往往需要同时处理课件、PDF、Word 文档、课堂笔记、错题记录和 AI 问答内容，但这些内容通常分散在不同软件里。学生每次复习都要频繁切换窗口，已经问过的问题容易遗忘，整理过的重点也难以再次利用。我们希望做的不是一个只能回答问题的聊天程序，而是一个能够真正参与复习流程、帮助知识沉淀和反复训练的 AI 学习助手。

在设计阶段，我们先把学习过程拆解为几个核心动作：资料进入、问题提出、AI 辅助理解、重点整理、练习生成和复习回顾。根据这个流程，项目形成了 Agents 学科入口、Topics 话题历史、Chat 对话区、Source 资料区、Notes 笔记区和复习工具等主要模块。这样的设计不是单纯按照技术功能堆叠，而是尽量贴近学生真实复习时的行为顺序，让用户可以围绕一个专题持续学习。

在实现过程中，我们使用 JavaScript、Node.js 和 Electron 搭建桌面端应用。主进程负责窗口、文件、数据目录、模型请求、知识库和笔记等系统能力；preload 层负责把受控 API 暴露给界面；renderer 层负责学习工作台界面、聊天交互、资料面板、笔记面板和消息渲染。项目还引入了本地知识库思路，对导入资料进行解析、切片、embedding 检索和可选 rerank，并在当前话题提问时把相关资料片段注入上下文，使 AI 回答更贴近用户正在复习的内容。

作品中的人工智能主要用于三个方面：一是结合当前 Source 资料进行问答和解释；二是根据对话或笔记内容生成深度分析；三是把已有学习内容转化为选择题、闪卡等复习材料。项目支持 OpenAI-compatible 风格的模型服务配置，可根据实际环境接入 OpenAI、DeepSeek、Ollama、LM Studio、OpenRouter、DashScope Compatible、OneAPI/NewAPI Compatible 等服务。我们没有把 AI 当作单独展示的功能，而是把它放进学习流程中，让 AI 在资料理解、知识整理和复习训练中发挥作用。

本作品为原创软件项目，核心问题分析、功能设计、学习流程拆解、界面组织和主要实现思路由项目成员完成。开发过程中参考了 Electron、Node.js、libSQL、DOMPurify、mammoth、pdf-parse、electron-builder 等开源项目和官方文档，并按照其开源许可用于工程实现。项目也使用 AI 工具辅助进行部分技术资料查询、代码问题分析、文案润色和测试思路整理，但作品的主题选择、功能取舍、系统结构、交互流程、核心代码实现与最终提交内容均由项目成员理解、修改和确认后完成，不属于 AI 一次性自动生成作品。

如为团队作品，可在最终报名时补充成员分工。例如：成员 A 负责整体需求分析、学习流程设计和答辩材料整理；成员 B 负责 Electron 主进程、文件管理、模型服务和知识库链路；成员 C 负责界面交互、消息渲染、Source/Notes 面板和演示视频制作。实际提交时应按真实分工填写。

## 环境说明

本作品为 Electron 桌面端软件作品，不需要外接硬件设备。作品已打包为 Windows x64 安装包、免安装目录版和单文件绿色版。评测时建议优先运行根目录下的 `1-先运行-UniStudy安装包.exe`，安装完成后从桌面快捷方式或开始菜单启动 UniStudy；源程序运行方式仅作为代码复现和开发调试的备用方案。

推荐运行方式：

1. 在 Windows 10 / Windows 11 64 位系统下，双击项目根目录中的 `1-先运行-UniStudy安装包.exe`。
2. 按安装向导完成安装；安装包为当前用户安装方式，通常不需要额外安装 Node.js、npm 或其他开发环境。
3. 安装完成后，从桌面快捷方式或开始菜单启动 UniStudy。
4. 如评测环境不便安装，可改用免安装目录版：打开 `2-免安装备用-UniStudy` 文件夹，双击其中的 `UniStudy.exe`；该目录版会把运行数据保存在同目录的 `UniStudyData` 文件夹中。
5. 首次进入应用后，在 Settings 中配置模型服务地址、API Key、默认模型以及 Source/KB 相关服务参数。配置完成后，新建或选择学科 Agent 和 Topic，导入资料后即可进行 AI 对话、笔记整理和复习工具生成。

主要开发与运行环境如下：

- 操作系统：Windows 10 / Windows 11，建议 Windows 11 x64。
- 编程软件/平台：Visual Studio Code；JavaScript / Node.js + Electron。
- 软件版本：Visual Studio Code 1.117.0；Node.js v22.17.1；npm v11.6.4；Electron v37.10.3。
- 主要依赖：electron-builder、@libsql/client、axios、mammoth、pdf-parse、pdf-poppler、sharp、DOMPurify、jsdom、Vitest 等。
- 数据存储：安装版默认使用当前用户的 `AppData\Roaming\UniStudyContest` 保存设置、Agent、Topic、聊天历史、附件、知识库和笔记；安装目录中的 `UniStudySeedData` 仅作为只读演示种子数据。免安装备用版会把运行数据保存在同目录的 `UniStudyData`，并通过 `.unistudy-portable` 标记启用。也可通过环境变量 `UNISTUDY_DATA_ROOT` 指定独立数据目录。
- 模型服务：需要在应用 Settings 中配置聊天模型服务地址、API Key、默认聊天模型；若使用 Source 资料检索增强能力，还需要配置 embedding 服务，启用 rerank 时还需要配置 rerank 服务。模型接口采用 OpenAI-compatible 风格，可接入兼容服务。
- 支持资料类型：PDF、DOCX、TXT、Markdown、CSV、HTML、JSON、XML、CSS 以及常见图片文件。

源程序备用运行方式：

1. 解压或克隆项目源代码。
2. 在源程序运行电脑上安装 Node.js v22.17.1 或兼容版本。
3. 在项目根目录执行 `npm install` 安装依赖。
4. 执行 `npm start` 启动开发版应用；Windows 环境也可以直接运行 `start.bat`，脚本会检查依赖并启动 Electron。

打包复现方式：

项目提供 Windows 打包脚本，可执行 `npm run pack:win` 生成目录版应用，或执行 `npm run dist:win` 生成安装包与单文件绿色版 exe。当前提交材料建议同时包含 Windows 运行程序和源程序：运行程序首选根目录下的 `1-先运行-UniStudy安装包.exe`；`dist/` 和免安装目录版属于本地打包产物，可按需重新生成，不建议作为源码仓库根目录内容长期保留。源程序包括 `src`、`scripts`、`vendor`、`package.json`、`package-lock.json`、`README.md`、`start.bat` 等源码和配置文件。

离线与联网说明：

应用的本地界面、话题历史、附件、笔记和已保存数据可以在本机保存和查看；AI 对话、embedding 检索、rerank、学习内容生成等核心智能能力依赖用户配置的模型服务，通常需要本地模型服务或联网 API 支持。若现场网络不可用，可提前准备可运行的本地模型服务或演示已保存的历史对话、资料、笔记和界面功能。
